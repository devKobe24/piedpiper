## 현재 계획

@CLAUDE.md

---

## 지시

위 계획을 읽고, 구현을 시작하기 전에 사용자에게 확인해야 할
미결 사항을 질문 리스트로 만든다.

`CLAUDE.md`가 없으면 명세 파일의 경로를 물어보고 멈춘다.

### 먼저 확인할 것

`.progress-report/clarify-*.md`가 이미 있으면 읽는다.

- 질문지는 있는데 하단에 확정된 답변이 없다 → 질문을 다시 만들지 않는다.
  기존 질문지를 다시 보여주고 답변만 받는다.
- 확정된 답변까지 있는데 `CLAUDE.md`에 "확정된 결정" 섹션이 없다 →
  질문지의 답변을 `CLAUDE.md`에 반영하는 것부터 한다.
- 둘 다 있다 → 새로 물을 것이 생겼는지 확인하고, 없으면 그렇다고 알린다.

### 규칙

1. 명세에 이미 적혀 있는 내용은 묻지 않는다.
2. 한 질문에 하나의 결정만 담는다.
3. 각 질문에 선택지를 2~4개 제시하고, 각 선택지가 이후 구현에
   어떤 영향을 주는지 한 줄로 덧붙인다.
4. 나중에 바꾸기 비싼 것부터 먼저 묻는다. 순서는 대체로
   기술 스택 → 데이터 모델 경계 → 인증 방식 → 외부 연동 범위 →
   배포 환경 → UI 세부사항.
5. 질문은 최대 7개. 그 이상이면 우선순위로 잘라낸다.
6. 사용자가 답할 수 없는 질문(내가 조사하면 되는 것)은 묻지 않는다.
   그런 항목은 따로 모아 "조사 대상"으로 분류한다.
7. 조사 대상 항목이 특정 질문의 답에 종속되면 그 조건을 함께 적는다.
   ("Q3이 B/C일 때만") 답변에 따라 불필요해지는 조사를 미리 걸러낸다.

### 출력 형식

```markdown
## 확인이 필요한 것

### Q1. <질문>
- A) <선택지> — <이후 구현에 미치는 영향>
- B) <선택지> — <영향>

### Q2. ...

## 조사 대상 (답변 후 /deep-research로 넘길 항목)
- <항목> (<종속 조건이 있으면 적는다>)
```

### 질문지 저장

질문 리스트를 출력하는 **동시에** `.progress-report/clarify-01.md`에 저장한다.
이미 있으면 번호를 올린다 (clarify-02.md).

대화가 끊기거나 세션이 바뀌어도 `Q1: A` 같은 짧은 답변을 해독할 수 있어야 한다.
질문지가 대화에만 남으면 답변과 질문의 연결이 끊어진다.

저장 형식은 출력한 것과 같되, 맨 위에 작성 시각을 적는다.

```markdown
# clarify 질문지

작성: <날짜>
대상: CLAUDE.md

## 확인이 필요한 것
...
```

### 답변을 받은 뒤

`Q1: A` 형태의 짧은 답변을 받으면 `.progress-report/clarify-*.md`를 읽어
선택지를 해독한다.

질문지 파일이 없고 대화에도 질문이 남아 있지 않으면 **추측하지 않는다.**
어떤 항목이 미결인지 나열하고, 선택지 문자 대신 값으로 답해 달라고 요청한다.

답변을 `CLAUDE.md`에 "확정된 결정" 섹션으로 반영한다.
반영 후 `.progress-report/clarify-*.md` 하단에 확정된 답변도 함께 기록한다.

```markdown
## 확정된 답변 (<날짜>)

| 질문 | 선택 | 값 |
|---|---|---|
| Q1 | D | Java 21 + Spring Boot 3 |
```

그리고 조사 대상을 반영한 `/deep-research` 명령 초안을 제시한다.
직접 실행하지 않는다 — `/deep-research`는 사용자만 시작할 수 있다.
